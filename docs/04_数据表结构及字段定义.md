## 1. 通用字段规范

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 主键 |
| created_at | TIMESTAMPTZ | 创建时间 |

## 11. propagation_edges

> **实现说明（migration 0005）**：`from_item_id` / `to_item_id` 均外键指向 **`raw_items`**
> （§11 未指明节点类型；传播关系是"内容之间"的关系，绑定原始层才能保证可追溯）；

## 13. market_bars

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 主键 |
| instrument_id | UUID FK | 标的 |
| timeframe | VARCHAR(10) | 1m/5m/15m/1h/4h/1d |
| open_time | TIMESTAMPTZ | K线开始 |
| close_time | TIMESTAMPTZ | K线结束 |
| open | NUMERIC(20,8) | O |
| high | NUMERIC(20,8) | H |
| low | NUMERIC(20,8) | L |
| close | NUMERIC(20,8) | C |
| volume | NUMERIC(28,8) | 成交量 |
| source_id | UUID FK | 来源 |
| collected_at | TIMESTAMPTZ | 采集时间 |
| effective_at | TIMESTAMPTZ | 可用时间 |

唯一：`instrument_id + timeframe + open_time`。

补充（团队批复新增，migration 0003）：按来源的唯一索引
`uq_market_bars_source_instrument_timeframe_open (source_id, instrument_id, timeframe, open_time)`。
`market_bars` 无 `symbol` 列（symbol 在 `instruments` 上且自带唯一约束，与 `instrument_id`
一一对应），故以 `instrument_id` 表达 symbol；该索引显式保证"同一来源内同一根 K 线不重复"，
而更严格的 `instrument_id + timeframe + open_time` 唯一约束继续保证跨来源也不重复。

> **⚠️ Phase 1 冻结遗留（技术债 TD-03）**：`4h` 周期**当前没有真实数据**。
> provider（Yahoo chart）不提供 `4h` 原生粒度，`market_collector` 会**跳过并告警**
> （不伪造、不上采样），因此本表中不存在 `timeframe = '4h'` 的行。
> 4h 必须由 **Processor 层**从 `1h`（或 `1m`）确定性聚合产生
> （`processed_items.processor_name = 'bar_aggregator'`），且聚合行只在子 K 线
> **已收盘**时才允许写入、`effective_at >= 最后一根子 K 线 close_time`（防泄漏）。
> Phase 1 冻结时**不实现**；详见根目录 `TECH_DEBT.md` TD-03。

> **⚠️ Phase 1 冻结遗留（技术债 TD-04）**：feed 未给出明确时区（RFC822 无 `GMT`/`-0400`、
> ISO8601 naive）的新闻**不会生成本表行**，只保留 `raw_items`
> （`published_at = NULL`、`effective_at = collected_at`、
> `raw_json.published_at_tz_ambiguous = true`），同时在 `collector_runs.warnings_json` 留下告警。
> **绝不猜测时区、绝不把 `collected_at` 冒充发布时间**（否则会系统性时间错位）。
> 是否放宽（登记 `sources.timezone` 后回填，或持续排除并标注覆盖率）由 Phase 2 决策；
> 详见 `TECH_DEBT.md` TD-04。

## 15. macro_events

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 主键 |
| event_code | VARCHAR(100) | CPI/FOMC/NFP等 |
| country | VARCHAR(50) | 国家 |
| event_at | TIMESTAMPTZ | 观测所属期（observation date；不是发布时间） |
| released_at | TIMESTAMPTZ | 该 vintage 的保守可用起点（非空） |
| vintage_end_at | TIMESTAMPTZ NULL | 被下一修订替代的排他边界；NULL=仍有效 |
| actual_value | NUMERIC(28,10) | 实际值 |
| forecast_value | NUMERIC(28,10) | 预期值 |
| previous_value | NUMERIC(28,10) | 前值 |
| unit | VARCHAR(30) | 单位 |
| source_id | UUID FK | 来源 |
| collected_at | TIMESTAMPTZ | 采集 |
| effective_at | TIMESTAMPTZ | 可用 |

> **⚠️ Phase 1 冻结遗留（技术债 TD-01 / TD-05 / TD-07）**：当前唯一写入方是
> `macro_collector`（FRED 官方公开 API `/fred/series/observations`），且**仅经过 Mock 测试、
> 尚未与真实 API 联调**（TD-01）。这带来三项已登记的限制：
> 1. `forecast_value` / `previous_value` **恒为 `NULL`**：FRED 观测不含预期值 / 前值，
>    禁止凭空推断；待 `econ_calendar_collector`（当前 `enabled=false`，未实现）实现后由日历源补全
>    （TD-05 / TD-07）；
> 2. `event_at` **保持 provider 原始粒度**（日 / 月 / 季，不重采样、不拉平）；
> 3. **Phase 3.0 W0-2（migration 0006）**：普通 FRED 最新修订值已禁止用于历史训练；采集器使用
>    `output_type=4`（Initial Release Only）分块回填首次发布值。因 API 只有日期精度，
>    `released_at = realtime_start 次日 00:00 UTC`（保守、不做日内猜测）；initial-release 数据的
>    `realtime_end` 可能是查询边界，故不冒充真实失效日，`vintage_end_at=NULL`。
>    `effective_at >= max(released_at, collected_at)`。
>    CSV 离线输入缺 `released_at` 时硬失败。同一观测期的修订值按
>    `(source_id,event_code,country,event_at,released_at)` 追加保存，禁止覆盖。
>    当前回填范围只证明“初值发布后可见”；完整修订链重建尚未交付，不得把 NULL
>    `vintage_end_at` 解读为“该值历史上从未修订”。
> 详见 `TECH_DEBT.md`。

## 44. Phase 2 表实现说明（migration 0005，Author Lab）

Phase 2 第一步新增 4 张表（`database/models/__init__.py::PHASE2_TABLES`）。
字段严格对齐 §10 / §11 / §19 / §20；本节只登记**文档未明确、但必须固定的实现层决策**
（由 `tests/integration/test_phase2_author_lab_schema.py` 与漂移测试逐条强制）。

| 表 | 幂等自然键（唯一约束） | 时间因果 CHECK | 其它 CHECK | 索引 |
|---|---|---|---|---|
| `author_opinions` | 无（见决策 4） | `created_at >= effective_at` | `confidence ∈ [0,1]`、`entry_low <= entry_high`、四项价格 > 0、枚举 3 项 | `(author_id, effective_at)`、`(stance, horizon)`、`author_post_id`、`instrument_id` |
| `propagation_edges` | `(from_item_id, to_item_id, relation_type, model_version)` | `created_at >= detected_at` | `from_item_id <> to_item_id`、`similarity/confidence ∈ [0,1]`、枚举 1 项 | `from_item_id`、`to_item_id` |
| `author_skill_snapshots` | `(author_id, as_of)` | `created_at >= as_of` | 六项分值 ∈ [0,1]、`sample_size >= 0` | 由唯一约束覆盖 |
| `author_weight_snapshots` | `(author_id, regime_type, horizon, information_type, as_of)` | `created_at >= as_of` | `weight ∈ [0,1]`、`exploration_weight ∈ [0,1]` | 由唯一约束覆盖 |

实现层决策（全部落地在 `database/models/author_lab.py` + migration 0005）：

1. **`horizon` 只允许 5 个值**：`15m/30m/1h/4h/1d`（`OpinionHorizon`）。刻意排除 `1m/5m`：
   它们只用于行情 K 线，不是 Phase 2 的前瞻评价窗口（`docs/05` Phase 2）。
2. **`information_type` 从 `MACRO/TECHNICAL/NEWS/...` 收敛为 6 个值**：
   上述三类 + `SENTIMENT` / `POSITIONING` + 兜底 `OTHER`；新增取值必须写新迁移。
3. **`author_weight_snapshots` 维度用哨兵 `'ANY'`**（`WEIGHT_CONTEXT_ANY`）而不是 NULL，
   否则唯一约束对 NULL 不去重，幂等失效（见 §20 注记）。
4. **`author_opinions` 不设自身唯一键**：一条帖子可产生多个标的 / 多个方向的观点；
   其幂等由上游 `processed_items(raw_item_id, processor_name, processor_version)` 唯一键
   + 提取器前置检查保证（与 Phase 1 加工层同一口径）。
5. **4 张表全部 append-only**：`database/protection.py` 已注册不可覆盖守卫；修正路径 =
   新 `parser_version` / `model_version` 产生新行（03 §10）。
6. **跨表时间因果不在数据库层强制**（与 Phase 1 的 `processed_items` 完全一致）：
   `author_opinions.effective_at >= author_posts.effective_at` 由提取器（`src/processors/timeline.py`
   的 `resolve_opinion_effective_at` + `assert_opinion_available_after_post`）保证，
   并由 `tests/leakage/test_opinion_timeline.py` 强制。
   > ✅**团队裁决（2026-09）**：**采纳该方案，不新增** `source_effective_at` 列。
   > 即：跨表不变式由应用层 + leakage 测试承担；单表可强制部分
   > （`created_at >= effective_at`）由 migration 0005 的 CHECK 承担。
7. **NULL 语义统一**：分值 / 价格 / 置信度 / 标的一律可空，NULL = "未计算 / 未给出"
   （禁止用 0 或默认标的冒充）；`UNKNOWN` 是 `stance` 的合法取值。

### 44.1 作者库（`authors` / `author_accounts`）的实现口径

落地于 `database/repositories/authors.py`（仓储）+ `database/repositories/audit.py`（审计）

8. **自然键与"不覆盖"口径**：`authors.canonical_name`（缺失时回退 `display_name`）、
   `author_accounts(source_id, external_account_id)`；`ensure()` / `upsert(update_existing=False)`
   命中既有记录时**原样返回、不做任何修改**（与 `instruments` / `sources` 种子同一口径，
   避免导入冲掉运维人工调整）。
9. **审计口径（谁改了、改前改后是什么）**：管理性修改（作者创建 / 改名 / 改状态 / 软删除；
   账号创建 / 改名 / 启停）**必写 `audit_logs`**（`before_json` / `after_json` 为列字段快照，
   UUID→str、datetime→ISO8601、Enum→value）；一次 CSV/种子导入额外写一条
   `authors.import` 汇总审计（来源、条数、问题清单）。
   **例外（显式取舍）**：`author_accounts.last_collected_at` 心跳属采集性写入，
   由每轮采集触发且已在 `collector_runs` 留痕，**不写审计**（否则审计表会被心跳淹没）。
10. **作者 + 平台账号是一个导入单元**：来源（`sources`）缺失时该行**整行跳过**并计入
    `problems`，不产生"没有账号的半个作者"；`seed_database(authors_csv=...)` 在存在
    `problems` 时选择**整批回滚 + 报错**（不留半成品），而库函数 `import_authors_from_csv`
    则上报问题并继续处理其它行（调用方语义不同，均已测试固定）。

### 44.2 加工与传播（`processed_items` / `author_opinions` / `propagation_edges`）的实现口径

11. **`processed_items` 没有 `error_message` 列**（Phase 1 冻结结构）：
    观点管道抽取失败时，异常类型与消息写入 `structured_json`
    （`{"exception": ..., "error_message": ...}`），状态置 `FAILED`；
    空文本帖子写 `SKIPPED` + `structured_json.status_reason`；
    抽不到观点也写一行 `SUCCESS` + `structured_json.no_opinion=true`
    （**已处理**语义，避免每轮重复解析同一帖子）。
12. **传播去重是"1 条原创 + N 条转载"的防重复计数机制**：
    `src/processors/propagation.py` 采用 TF-IDF 余弦相似度（阈值 `0.80`，
    实测：同文 = 1.000、"转发：…"噪声 ≈ 0.82、方向相反 ≈ 0.60）；
    方向恒为 **早 → 晚**，关系优先级 `REPOST`（同文）→ `SAME_SOURCE`（同来源）→
    `SEMANTIC_SIMILAR`；独立观点数 = 连通分量数（1+99 → **1**）。
    `model_version` 编码「切分策略 + n-gram + 阈值」（如
    `tfidf-cjk-ngram-v1-n2-thr0.80`），改参数必须整体重算并写新版本行（append-only）。
13. **处理器版本即幂等键**：`processed_items(raw_item_id, processor_name, processor_version)`
    为唯一键；升级处理器/模型 = 换 `processor_version` → 同一帖子被重新处理，
    旧行保留（`tests/integration/test_opinion_pipeline.py` 已固定该行为）。
