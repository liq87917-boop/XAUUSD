# GOLD-AI 分阶段开发路线图 V1.0

## 总体原则

不要一次把所有高级算法堆进去。

正确顺序：

```text
数据可靠
→ 时间可靠
→ 标签可靠
→ 基准模型可靠
→ 策略验证可靠
→ 动态权重
→ 进化
→ 自动研究
```

系统始终保持：

```env
LIVE_TRADING=false
```

直到未来单独设计、审计、授权实盘模块。

## 承接 Phase 1 遗留（Phase 2 开工前必须先决）

Phase 2 的输出（作者观点与技能评分）直接依赖 Phase 1 的时间语义与数据完整度，因此：

1. **新闻时区策略裁决（TD-04）**：决定「为 `sources` 登记默认时区后回填 `news_events`」
   还是「持续排除此类新闻并按覆盖率标注」。这决定 Author Lab 可用文本量，
   **必须在建立 `author_opinions` 之前定稿**（回填必须新增版本，禁止覆盖原始层）。
2. **PostgreSQL 端到端验证（TD-02）**：观点抽取的写入量远大于采集，
   必须在 Phase 2 前完成 PG 上的采集 + 管道验证。
3. **4h K 线（TD-03）**：Author Skill 的 `4h` 前瞻评价窗口依赖 Processor 层的聚合结果。
4. **Scheduler（TD-09）**：观点抽取与前瞻评价需要周期性任务，与采集共用调度框架。
