# 03_数据库完整设计.md

# GOLD-AI 数据库完整设计 V1.0

## 1. 数据库目标

数据库设计必须支持：

- 原始数据永久保存
- 加工数据版本化
- 时间因果追踪
- 作者技能快照
- Regime 历史快照
- Alpha / Prediction 追溯
- Strategy DNA 与版本
- Backtest / OOS / Walk-forward
- Paper Trading
- Performance Attribution
- Evolution
- Experiment Reproducibility
- Scheduler / Job / Audit

主数据库建议 PostgreSQL。

> **备注（团队批复）**：生产 / 研究环境**建议并必须切换为 PostgreSQL** ——
> JSONB / 原生 UUID / TIMESTAMPTZ、并发写入与按时间分区的能力都依赖它。
> 本地开发与自动化测试可临时使用 SQLite（`sqlite+pysqlite:///...`），但 SQLite
> 不保存时区偏移、缺少上述原生类型，**不得用于采集数据与研究事实数据的长期存储**。
>
> 当前实现方式：
> - `database/types.py` 同时映射 PostgreSQL 原生类型与 SQLite 测试变体（仅影响测试库 DDL）；
> - CI `postgres` 作业 + `scripts/check_pg_schema.py` 在真实 PostgreSQL 上校验
>   原生类型（uuid / jsonb / timestamp with time zone）与种子幂等；
> - 所有涉及数据库的模块顶部都标注了该约束（settings / session / types / conftest）。

## 5. 时间字段规范

所有时间保存 UTC。

必须区分：

- `published_at`
- `collected_at`
- `effective_at`
- `event_at`
- `created_at`
- `updated_at`

金融研究中严禁用 `created_at` 替代 `effective_at`。

---

## 6. 主键策略

推荐：UUID v7。

原因：

- 全局唯一
- 分布式友好
- 时间有序
- 避免暴露自增规模

数据库：`uuid` 类型。

---

## 7. 枚举规范

建议数据库中使用 varchar + 应用层 Enum，减少数据库 enum 迁移困难。

主要枚举：

```text
stance: LONG SHORT FLAT UNKNOWN
regime: TREND_UP TREND_DOWN RANGE HIGH_VOLATILITY LOW_VOLATILITY NEWS_DRIVEN UNKNOWN
alpha_type: AUTHOR NEWS MACRO TECHNICAL MARKET_STRUCTURE
strategy_status: DRAFT CANDIDATE CHALLENGER CHAMPION RETIRED REJECTED
job_status: PENDING RUNNING SUCCESS FAILED RETRYING SKIPPED
trade_side: BUY SELL
order_status: CREATED SUBMITTED PARTIALLY_FILLED FILLED CANCELLED REJECTED CLOSED
```

## 10. 不可覆盖原则

禁止 UPDATE 覆盖的主要研究事实表：

- raw_items
- processed_items
- author_opinions
- market_regimes
- feature_snapshots
- alpha_signals
- predictions
- author_skill_snapshots
- author_weight_snapshots
- strategy_versions
- backtest_runs
- performance_snapshots

修正数据时：

- 创建新版本
- 旧记录标记 superseded
- 保留 superseded_by_id

## 11. 数据版本

`data_versions` 用于记录：

- 数据集名称
- 起止时间
- 数据哈希
- 生成时间
- 来源范围
- 过滤规则
- 版本号

任何训练 / 回测必须绑定一个 `data_version_id`。

## 12. Experiment 追溯

每个 experiment 至少关联：

- code_version_id
- data_version_id
- feature_set_id
- model_version
- parameters_json
- random_seed
- started_at
- finished_at
- result_summary_json

---

## 13. JSONB 使用规则

JSONB 适用于：

- LLM 原始结构化输出
- Strategy DNA
- Parameters
- Model metadata
- Explainability output

不应使用 JSONB 替代高频查询字段。

---

## 14. 金融数值类型

价格：`NUMERIC(20,8)`

概率：`NUMERIC(12,10)`

收益率：`NUMERIC(18,10)`

金额：`NUMERIC(20,8)`

数量：按资产决定 `NUMERIC(20,8)`

禁止对核心金额使用 binary float。

---

## 15. 外键策略

原则：

- 核心链路必须外键约束
- 海量时序可视性能选择弱约束
- 删除使用软删除
- 原始事实数据禁止级联物理删除

---

## 16. 数据保留

- Raw data：永久
- Processed data：永久
- Feature snapshots：至少覆盖所有训练与回测版本
- Logs：普通日志 90～180 天；Audit 永久或长期归档
- Model artifacts：所有进入正式实验的版本长期保留

---

## 17. 数据质量规则

每批次至少检查：

- null ratio
- duplicate ratio
- timestamp monotonicity
- abnormal gap
- future timestamp
- price <= 0
- OHLC invalid
- impossible probability
- orphan foreign keys

---

## 18. 恢复与备份

开发环境：每日 dump。

研究正式环境：

- PostgreSQL 每日全备
- WAL 增量
- Object Storage versioning
- 配置和模型元数据备份

---

## 19. 数据库迁移原则

所有结构修改通过 Alembic。

禁止：

- 直接生产数据库手改
- 删除历史 migration
- 修改已经上线的 migration

每次 migration 必须可回滚或提供明确不可回滚说明。

---

## 20. 数据库完成判定

数据库设计必须能够完整表达：

```text
原始信息
→ 结构化理解
→ 作者观点
→ 时间对齐
→ Regime
→ Feature
→ Alpha
→ Prediction
→ Strategy Version
→ Risk
→ Backtest / Paper
→ Performance
→ Attribution
→ Evolution
```
