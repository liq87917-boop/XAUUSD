# GOLD-AI 测试与验收标准 V1.0

## 1. 总体测试原则

本系统是研究型金融系统，测试不能只验证“程序不报错”。

必须同时验证：

- 功能正确
- 数据正确
- 时间正确
- 无未来数据泄漏
- 回测可复现
- 风险门禁有效
- 策略版本不可覆盖
- 任务可重试
- 数据可追溯

---

## 2. 测试层级

### Unit Test

验证单函数、单类。

### Integration Test

验证：

- DB
- Redis
- Worker
- API
- Collector + DB
- Processor + DB

### Regression Test

Bug 修复必须保留回归测试。

### Data Quality Test

检查数据本身。

### Leakage Test

专门测试时间因果。

### Backtest Validation Test

检查交易计算和成交时序。

### End-to-End Test

验证完整链路。

- [ ] Redis 正常
- [ ] API 正常
- [ ] Worker 正常

---

## 4. Phase 1 数据采集验收

### Collector

- [ ] 同一记录重复采集不会生成重复 RawItem
- [ ] 网络失败可重试
- [ ] 达到最大重试后记录 FAILED
- [ ] 一个 Collector 失败不影响其他 Collector
- [ ] 支持 cursor/checkpoint
- [ ] collector_run 有统计数据

### Raw Data

- [ ] source_id 正确
- [ ] source_record_id 唯一
- [ ] content_hash 正确
- [ ] published_at 存在或明确 NULL 原因
- [ ] collected_at 存在
- [ ] effective_at 正确
- [ ] 原始 JSON 保存
- [ ] 原始数据不可覆盖

### Market Bar

- [ ] OHLC 满足 high >= max(open,close)
- [ ] low <= min(open,close)
- [ ] price > 0
- [ ] K线时间不重复
- [ ] timeframe 正确
- [ ] 时区正确

### 连续稳定性

建议 Phase 1 正式验收前连续运行 7 天。

目标：

- Collector 成功率 ≥ 98%（排除外部源长期不可用）
- 重复数据率 < 0.5%
- 数据时间错位严重错误 = 0

---

## 5. Phase 2 Author Lab 验收

抽样至少 200 条观点人工检查。

### Stance

目标：

- LONG/SHORT/FLAT/UNKNOWN 分类准确率建议 ≥ 90%

### Horizon

- 可明确表达周期的文本，抽取准确率建议 ≥ 85%

### Entry / SL / TP

- 明确数字表达的样本准确率建议 ≥ 90%

### Confidence

- 数值必须在 0～1

### 传播去重

构造：

- 原作者 1 条
- 99 个复制帖子

系统不得把它们作为 100 个独立观点。

### Author Skill

必须验证：

- 少量样本不能轻易高分
- 样本量增大后可信度提升
- 不同 horizon 分开统计
- 不同 regime 可分开统计

---

## 6. Phase 3 Alpha / Prediction 验收

### Leakage Test：最高优先级

每一个 feature_snapshot：

```text
max_effective_at <= as_of
```

每一次 prediction：

```text
feature_snapshot.as_of <= prediction_at
```

构造未来数据注入测试：

- 人为增加 prediction_at + 1min 的信息
- 系统必须拒绝或测试失败

### Train/Test Split

必须按时间切分。

禁止随机 shuffle 整个时间序列后 train_test_split。

### Baseline

至少与以下比较：

- random
- always long
- simple momentum
- simple MA baseline

### Calibration

检查：

- Brier Score
- calibration curve

### OOS

任何“有效 Alpha”必须有 OOS 数据支持。

---

## 7. Phase 4 Backtest 验收

### 成交时序

禁止：

- 使用 bar close 形成信号
- 再用同一个 bar open 成交

### 成本

必须测试：

- fee=0
- fee>0
- slippage=0
- slippage>0
- spread=0
- spread>0

加成本后收益应符合方向性预期。

### 版本

修改 Strategy DNA 后：

- 必须生成新 version
- 老版本仍可回测

### Reproducibility

相同：

- code version
- data version
- strategy version
- seed

重复运行结果应一致或在明确允许的随机误差范围内。

### Walk-forward

训练窗口不得看到未来测试窗口。

### OOS

OOS 期间不能参与参数优化。

---

## 8. Phase 5 Risk 验收

必须构造以下场景：

### 单笔风险超限

期望：拒绝。

### 总暴露超限

期望：拒绝或降仓。

### 最大回撤触发

期望：拒绝新订单。

### 高波动

期望：降低仓位。

### 重大新闻窗口

期望：按规则限制。

### 连续亏损

期望：降杠杆。

### 数据缺失

期望：NO TRADE。

### 模型异常

期望：NO TRADE。

---

## 9. Paper Trading 验收

### Order State

验证完整状态流。

### Partial Fill

一张订单分 3 次成交，最终：

- filled qty 正确
- avg price 正确
- fee 正确

### PnL

BUY 和 SELL 都要测试。

### Slippage

模拟滑点必须进入实际 fill_price。

### Risk Integration

Risk `allowed=false` 时不能生成 SUBMITTED order。

---

## 10. Phase 6 Ensemble 验收

### Independence

复制观点不应线性提高总信号。

### Weight Condition

同一作者在：

- TREND
- RANGE

权重允许不同。

### Ablation

移除某作者后：

- 结果可重新计算
- contribution 有记录

### Baseline Compare

Dynamic Ensemble 必须与：

- equal weight
- static weight

进行 OOS 比较。

---

## 11. Phase 7 Evolution 验收

### Mutation

必须保留 parent strategy。

### Crossover

必须保留两个 parent。

### Promotion Gate

构造：

- Backtest 极好
- OOS 极差

期望：不得 Champion。

构造：

- Backtest 好
- OOS 好
- Paper 超最大回撤

期望：不得 Champion。

### Audit

每次 promote/demote/retire 都有记录。

---

## 12. Scheduler 验收

30 分钟任务链：

```text
Collect
→ Process
→ Timeline
→ Opinion
→ Regime
→ Alpha
→ Strategy Candidate
→ Risk
→ Paper
→ Evaluation
→ Evolution
```

测试：

- 中间某一步失败
- 重启 worker
- 断点恢复

不得重复生成不可幂等数据。

---

## 13. 数据质量验收

每日检查：

- Duplicate Ratio
- Missing Ratio
- Timestamp Delay
- Market Gap
- Invalid OHLC
- Abnormal Price Jump
- Source Health
- Parser Failure Rate

异常必须能在 Dashboard 看见。

---

## 14. 性能要求

MVP 阶段目标：

- 常用查询 API P95 < 500ms（不含复杂研究任务）
- Dashboard 常规页面加载 < 3s
- 30 分钟调度必须在下一轮开始前完成常规主链
- 长任务必须异步执行

复杂 Backtest/Training 不要求同步接口完成。

---

## 15. 安全验收

必须确认：

- [ ] 默认 LIVE_TRADING=false
- [ ] 无真实券商 secret 硬编码
- [ ] API key 不入 Git
- [ ] `.env` 在 `.gitignore`
- [ ] Audit Log 可查询
- [ ] 生产配置与开发配置分离
- [ ] Risk 不可被 Strategy 绕过

---

## 16. Release Gate

每阶段完成前必须：

```text
Unit Tests       PASS
Integration      PASS
Regression       PASS
Data Quality     PASS
Leakage Tests    PASS（适用阶段）
Migration        PASS
Build            PASS
Security Gate    PASS
```

存在关键 FAIL 时不得标记 Phase 完成。

---

## 17. 最终 V1.0 验收

完整闭环必须实现：

```text
Source
→ Raw Data
→ Understanding
→ Timeline
→ Author Intelligence
→ Regime
→ Alpha
→ Prediction
→ Meta
→ Strategy
→ Risk
→ Backtest / Paper
→ Performance
→ Attribution
→ Evolution
```

同时满足：

1. 任意 Prediction 可追溯到原始数据。
2. 任意 Backtest 可复现。
3. 任意 Strategy 有完整版本和 DNA。
4. 任意作者权重变化有原因。
5. 系统能够输出 NO TRADE。
6. 可以证明边际 Alpha，而不是只有相关性。
7. 新策略必须通过 OOS 和 Paper Gate。
8. 默认不允许实盘。
