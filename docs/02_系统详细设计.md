## 系统详细设计说明书 V1.0

> 本文档承接《01_系统总体架构设计》，将总体架构细化为可直接开发的模块、服务、接口、任务流、状态机和目录结构。

---

## 1. 设计目标

GOLD-AI 的目标不是构建“博主投票器”，而是建立一套可持续学习的信息源 Alpha 研究系统。系统围绕黄金市场，将微博财经信息、新闻、宏观数据、行情、多模态图片和技术图表统一纳入时间因果框架，通过作者画像、市场状态识别、Alpha 建模、策略生成、风险控制、回测、模拟盘和进化学习形成闭环。

核心设计原则：

1. 研究优先，默认仅回测和模拟盘。
2. 原始数据不可覆盖，所有加工结果版本化。
3. 严格时间对齐，禁止未来数据泄漏。
4. 预测、策略、风险完全解耦。
5. 所有实验、信号、策略、权重变化可追溯、可复现。
6. 模型复杂度低于数据质量和验证科学性优先级。
7. LLM 负责理解和研究辅助，不直接决定真实仓位和真实下单。
8. `LIVE_TRADING=false` 为系统默认且受配置硬门禁保护。

## 5. 核心模块详细设计

## 5.1 Collectors 数据采集

### 职责

采集：

- 微博财经作者及帖子
- 帖子图片、图表、研报截图
- 国内外财经新闻
- 宏观事件及实际值/预期值/前值
- XAUUSD
- COMEX Gold
- 国内黄金相关数据
- DXY
- 美债收益率 / 实际利率
- USD/CNY
- 原油、白银、BTC 等代理资产

### 统一采集接口

```python
class BaseCollector:
    source_name: str

    async def collect(self, start_at, end_at) -> list[RawItem]: ...
    async def health_check(self) -> CollectorHealth: ...
```

### 关键要求

- 每条原始数据必须生成 `source_record_id`
- 保存 `published_at`
- 保存 `collected_at`
- 保存 `effective_at`
- 保存原始内容哈希 `content_hash`
- 重复采集必须幂等
- 原始数据只追加，不覆盖

---

## 5.2 Processors 数据处理

处理链：

```text
Raw Item
→ Normalize
→ Deduplicate
→ Language Detect
→ OCR / Vision
→ NLP Parse
→ Entity Extraction
→ Event Extraction
→ Opinion Extraction
→ Structured Record
```

输出不得覆盖原始数据，必须生成独立版本。

### 状态

- PENDING
- PROCESSING
- SUCCESS
- FAILED
- RETRYING
- SKIPPED

每个 Processor 需要记录：

- processor_name
- processor_version
- input_id
- output_id
- started_at
- finished_at
- error_message

## 5.3 多模态理解

### 文本任务

输出：

- entities
- event_type
- stance: LONG / SHORT / FLAT / UNKNOWN
- confidence
- horizon
- entry_low / entry_high
- stop_loss
- take_profit
- rationale
- information_type

### 图片任务

三级处理：

- Level 1：OCR
- Level 2：K线/趋势线/支撑阻力/均线/MACD/RSI/突破结构识别
- Level 3：转化为可回测的结构化交易意图

Level 3 必须保留 `visual_parser_version`。

## 5.4 Timeline 时间对齐

统一所有数据的时间语义：

- published_at：外部世界首次公开时间
- collected_at：系统采集时间
- effective_at：系统允许使用该数据的最早时间
- event_at：事件本身发生时间

训练和回测必须使用：

```text
feature.effective_at <= prediction_at
```

任何违反此规则的数据禁止进入训练和回测。

## 5.12 Risk Engine

风险引擎必须独立于预测。

规则：

- Risk Budget
- Position Sizing
- Max Risk Per Trade
- Max Exposure
- Max Drawdown Guard
- Volatility Scaling
- News Event Guard
- Correlation Guard
- Consecutive Loss Deleveraging
- Data/Model Failure → NO TRADE

风险输出必须包含：

- allowed: bool
- rejection_reasons[]
- recommended_position
- max_position
- risk_score

风险层拥有最终否决权。

### 策略进化

- Champion

## 6. 30 分钟调度流程

每 30 分钟一轮：

```text
T+0  Collect
T+1  Normalize / Deduplicate / OCR / NLP
T+2  Timeline Alignment
T+3  Author Opinion + Propagation Graph
T+4  Regime Update
T+5  Alpha + Prediction
T+6  Candidate Strategy + Risk Gate
T+7  Research Signal + Paper Trading
T+8  Mature Prediction Evaluation
T+9  Skills / Weights / Evolution Update
```

每一阶段都必须：

- 有 task_id
- 幂等
- 支持失败重试
- 支持断点续跑
- 记录输入/输出版本
- 单个采集器失败不拖垮整轮

## 12. 非功能要求

### 可追溯
任何预测必须可以逆向追踪到：

```text
Prediction
→ Alpha
→ Features
→ Structured Event / Opinion
→ Raw Source
```

### 可复现
任何实验必须记录：

- git_commit
- dataset_version
- feature_version
- model_version
- parameters
- random_seed
- environment

### 数据一致性

- UTC 保存时间
- 前端按用户时区展示
- Decimal 保存价格和金额
- 禁止 float 存储关键金融金额

## 13. MVP 边界

第一版不做：

- 实盘交易
- 自动高杠杆仓位
- 深度强化学习
- 全量 1000 作者
- 复杂深度学习端到端模型
- 无验证的策略自动上线

第一版优先完成：

- 50～100 作者
- 30 分钟稳定采集
- XAUUSD 多周期行情
- 文本观点抽取
- 基础 Regime
- Alpha Benchmark
- Walk-forward 回测
- Paper Trading
