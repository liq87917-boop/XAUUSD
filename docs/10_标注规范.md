## 1. 目的与适用范围

**目的**：为"把作者说了什么转成结构化、可验证的预测事件"提供统一、可复核、可复现的
人工判定标准，使以下三件事成为可测量的事实，而不是主观印象：

1. 抽取器（Mock 正则版 / 后续 LLM 版）输出的字段是否与人工判断一致；
2. 不一致是"抽取错误"还是"规范歧义"（后者必须改本规范，而不是改抽取器去迎合）；
3. 抽查结果可按来源 / 周期 / 信息类型分层追踪，供 Phase 3 的 Alpha 研究判断数据可信度。

**适用范围**
- 适用：`author_posts`（作者帖子文本）→ `author_opinions` 的字段抽取与评价；
- 也适用于新闻文本（`news_events` 来源的正文）产生的观点抽取——字段定义相同；
- **不适用**：Phase 3 的 Alpha / 特征 / 回测评价（那要用市场结果而非人工标准）。

**本阶段数据来源（团队裁决）**：**不采集微博**。作者身份来自"机构 / 分析师 RSS 账号"
或本地 CSV 模拟导入；微博属 Phase 2 后期 / Phase 3 扩展。

## 2. 标注对象、抽样与样本结构

### 2.1 标注对象
- 单位是**一条 `author_posts` 记录**（含其原文正文 `text_content` 与媒体标记 `has_media`）；
- 一条帖子可以有 **0 条 / 1 条 / 多条**观点（例如同时看多 XAUUSD、看空 DXY），
  因此标注表是 1 : N：`post_id` 重复出现即为多观点；
- "0 条观点"必须显式标注（`no_opinion=true`），**不得留空**——留空会被误算成"漏抽"。

### 2.2 抽样方法（200 条）
- 从当前已落库的 `author_posts` 中**随机**抽取 200 条；随机种子写入结果文件（可复现）；
- **分层约束**（避免样本偏差）：
  - 来源（`author_accounts.source_id`）尽量均衡，单一来源占比 ≤ 40%；
  - 时间覆盖至少 5 个不同交易日；
  - 文本长度分档（≤50 字 / 51–200 字 / >200 字）各占约 1/3；
  - 含媒体（`has_media=true`）的样本 ≥ 20 条（用于校验 Level-1 OCR 后续阶段）。
- **对抗样本必配**（每类 ≥ 10 条，否则抽取器分数虚高）：
  | 类型 | 示例 | 期望标注 |
  |---|---|---|
  | 明确方向 | "2380 附近做多，目标 2450" | LONG + 点位 |
  | 条件性观点 | "若跌破 2380 则转空" | UNKNOWN（条件未满足）+ rationale 记条件 |
  | 引用他人 | "某机构认为金价将跌破 2300（作者未表态）" | UNKNOWN + rationale 标 `quote-only` |
  | 事后复盘 | "昨天 2380 的多单已经止盈" | UNKNOWN（不构成前瞻观点） |
  | 反问 / 反讽 | "现在还有人敢做多吗？" | UNKNOWN（除非有明确方向词） |
  | 纯信息播报 | "美国 8 月 CPI 同比 3.2%" | UNKNOWN + information_type=MACRO |
  | 图表无文字 | 图片 + "看图" | UNKNOWN + 标 `image_only=true` |
- 抽样脚本（**已交付**：`scripts/sample_annotation_set.py`）负责：随机 + 分层 + 去重
  （`content_hash`）+ 导出标注 CSV（列定义见附录 A）+ 写入随机种子与分层达成情况；
  用法：`python -m scripts.sample_annotation_set --limit 200 --seed 20260912`；
  作者库尚未导入时可用 `--input-csv logs/posts.csv` 演练（团队裁决：先用机构/分析师 RSS + 本地 CSV）。
- **演练数据（合成，已交付）**：`scripts/generate_mock_posts.py` 可生成 250 条结构完整的
  合成博文到 `logs/posts.csv`（每行 `is_mock=true` + `mock_batch`，来源取自已注册 NEWS 来源，
  **不含微博**），其中：
  - 长度三档（≤50 / 51–200 / >200 字）约 4:3:3，含媒体样本 ≥20 条，覆盖 ≥5 个交易日；
  - **对抗样本 8 类，各 15~17 条**（条件性 / 引用他人 / 事后复盘 / 双重否定 /
    点位方向不一致 / 纯信息播报 / 反问反讽 / 图表无文字），保证 200 条抽样后
    **每类仍 ≥10 条**（满足本节要求，有测试锁定）；
  - `effective_at = max(published_at, collected_at)`，并刻意含"缺发布时间"与
    "采集早于发布"两类时间边界样本（演练 §3）；
  - 末尾 5 条"同文转载"用于演练内容去重。
  命令：`python scripts/generate_mock_posts.py`（已存在时拒绝覆盖，加 `--force` 才覆盖）；
  `--input-csv` 指向的文件不存在时，抽样脚本会**自动生成**该批数据并在 stderr 打出醒目警告。
- **来源可追溯**：抽样元数据 `annotation_sample.meta.json` 记录
  `input_is_mock` / `input_mock_rows` / `input_mock_batch`（输入是否合成数据、多少行、批次号）；
  合成数据**只用于跑通流程与校准标注标准**，任何准确率结论必须用真实数据复跑。
- **文件编码**：输入 CSV 与标注 CSV 一律以 `utf-8-sig` 写出（Excel 双击中文不乱码），
  读取时兼容"有 BOM / 无 BOM"两种（列名大小写不敏感，支持 `id` / `source` / `content` 等别名）。

### 2.3 盲标要求
标注者在标注时**不得查看抽取器输出**（避免锚定效应）。抽取结果与人工标注分文件保存，
比对环节才合并；`annotation_version` 记录"规范版本 + 标注人 + 日期"。

## 3. 时间语义（防未来数据泄漏，最高优先级）

标注与抽取都必须遵守"当时能知道什么"这一唯一标尺：

1. **标注只能用帖子正文 + 该帖的 `published_at`**；禁止使用标注当天之后的行情、新闻、
   政策结果等任何信息。若标注者发现自己必须借助事后信息才能判定 → 该条标为 UNKNOWN
   并置 `leakage_suspect=true`，**从准确率统计中剔除**（但保留在文件中备查）。
2. **观点的时间起点 = `author_posts.effective_at`**（= `max(published_at, collected_at)`），
   不是 `published_at`，也不是"现在"。所有前瞻评价窗口（15m/30m/1h/4h/1d）
   都从 `effective_at` 起算。
3. **数据库强制**：`author_opinions.effective_at >= author_posts.effective_at`
   由提取器保证，并由带 `leakage` 标记的测试强制（`docs/04 §44` 决策 6）；
   同时 `created_at >= effective_at` 由数据库 CHECK 直接拒绝违规写入。
4. 时间无法确定（`published_at` 为空）的帖子：`effective_at = collected_at`，
   仍可参与标注，但必须记录 `time_precision=collected_only`，在报告中单独统计占比。

## 4. 字段判定规则

字段名与 `author_opinions` 列名一一对应（`docs/04 §10`）。

### 4.1 `stance`（LONG / SHORT / FLAT / UNKNOWN）

| 取值 | 判定标准（满足其一即成立） |
|---|---|
| `LONG` | 明确看涨/做多：出现"看多/做多/买入/加仓/上破/看涨/目标 2450"等**方向性动词或判断**，或给出高于当前价的入场/目标 |
| `SHORT` | 明确看跌/做空：出现"看空/做空/卖出/减仓/跌破/目标 2300"等 |
| `FLAT` | 明确表示**不参与/观望/区间/已离场**："观望/等信号/区间震荡不追/已平仓" |
| `UNKNOWN` | 无法判定方向，或属于第 2.2 节的对抗样本；**这是合法且必要的输出** |

**边界规则（严格执行，避免"过度解读"）**

1. **条件性观点**（"若跌破 2380 则看空"）：条件未满足 → `UNKNOWN`，`rationale` 记完整条件句。
   抽取器若直接给 `SHORT` 即判**错误**（会制造虚假信号）。
   **注意**（2026-09-13 裁决）：方向判 `UNKNOWN` **不等于**丢弃该条——文本给出的
   **点位与信息类型仍必须输出**，见 §4.9 第 1/4 条。
2. **引用他人意见**且作者未表态 → `UNKNOWN` + `rationale` 标 `quote-only`。
3. **事后复盘**（"昨天多单止盈"）→ `UNKNOWN`（不构成前瞻观点）。
4. **反讽 / 反问**（"还有人敢做多吗"）：仅当出现明确方向词且语境不矛盾才判方向，否则 `UNKNOWN`。
5. **含糊倾向**（"不排除继续上行"）：`可能/不排除` → 可判 LONG 但 `confidence ≤ 0.4`；
   整帖只有这一句倾向时记 `UNKNOWN` 并备注。同一批标注内必须口径一致（由 §6 的 Kappa 检查保证）。
6. **同一帖多方向**：拆成多条观点（各一行），禁止合并为"中性"。

### 4.2 `horizon`（15m / 30m / 1h / 4h / 1d / 空）

- 只允许上述 5 个值（数据库 CHECK 强制，`1m/5m` 会被拒绝）；**正文没有周期线索时留空**，
  禁止默认填 `1d`。
- 词典映射（须在 `rationale` 写明依据词）：

  | 正文措辞 | horizon |
  |---|---|
  | "几分钟 / 超短线 / 分钟级" | `15m` |
  | **"短线思路" / "短线观望" / "思路更新"（计划型、无其它周期词）** | **`15m`** |
  | "半小时 / 半小时内 / 30 分钟" | `30m` |
  | "短线 / 日内"（执行型） | `1h` |
  | "半天 / 几小时 / 美盘 / 4 小时级别" | `4h` |
  | "中线 / 本周 / 趋势 / 日线" | `1d` |
  | 无线索 | 留空（NULL） |

- **2026-09-13 二次裁决（周期映射补丁）**：人工标注把"**短线思路**"映射为 `15m`
  （依据 `mock-post-0028`：正文"黄金短线思路：观望"，人工判 `15M`）。
  口径区分：**"思路 / 观望"这类计划型表述 → `15m`**；
  **"短线 / 日内"这类执行型表述（带操作动作）→ `1h`**；模型留空或判 `1d` 均计**未命中**。
- **实测经验（`llm-deepseek-v6`/`v13`）**：本表即**实测最优**的映射（200 条语料上
  `horizon` 人工子集 100%）；曾试过"按时段词拆表 + 栏目名不计数"的写法，
  反而把 `30m / 4h / 1d` 多格判错 → 已回退。**不要**再为个别样本细化本表。
- "短线"默认映射到 `1h`（不是 1d）——这是最容易产生分歧的一项，标注务必写依据词。

### 4.3 `confidence`（0~1，可空）

按**文本强度**打分，与作者水平、胜率、粉丝数**无关**：

| 分数 | 情形 |
|---|---|
| `0.9` | 极明确：方向词 + 明确点位 + 无对冲措辞 |
| `0.7` | 明确方向词，但无具体点位 |
| `0.5` | 倾向性措辞（"倾向 / 大概率 / 偏多"） |
| `0.3` | 弱暗示（"不排除 / 或许 / 留意"） |
| 空 | 无法判断强度（例如纯数据播报，此时通常也是 UNKNOWN） |

抽查时 `confidence_validity` 检查两件事：(a) 与人工分档的相关性；
(b) **单调性**——方向越明确分档越高，不允许"含糊文本给 0.9"。

> **实现口径（已批准，`RegexOpinionExtractor` 与人工标注保持一致）**：
> `不排除 / 或许 / 也许 / 可能` 属"弱暗示"档 → `confidence ≤ 0.4`（§4.1.5）；
> `倾向 / 大概率 / 预计 / 有望` 属"倾向性措辞"档 → `confidence ≤ 0.5`；
> 其余按文本强度取 `0.7`（仅方向词）或 `0.9`（方向词 + 入场/止损/目标齐全）。

### 4.4 价格字段 `entry_low` / `entry_high` / `stop_loss` / `take_profit`（可空）

- **只标注正文明确给出的数值**，禁止推算、禁止用"当前价"补齐（缺失即留空）。
- 区间："2380-2395 区间做多" → `entry_low=2380`、`entry_high=2395`；
  单点："2380 做多" → `entry_low=entry_high=2380`。
- 单位统一为 **XAUUSD = 美元/盎司**；"24.5 万"、"2450 点"等无法确定单位的表述 → 留空。
- 方向一致性（标注复核会校验）：`LONG` 应满足 `stop_loss < entry <= take_profit`；
  `SHORT` 应满足 `take_profit <= entry < stop_loss`；违反者视为标注错误。
- 数据库层另强制：四项价格 > 0、`entry_low <= entry_high`。

> **抽取口径（宁可留空，不可猜错）**：只有当数字与价格关键词的间距 ≤2 字符时才认为它属于
> 该字段；出现多个候选时按**方向一致性**筛选（`LONG` 的止损必须低于入场价、目标必须高于入场价，
> `SHORT` 反之），仍无法唯一确定的一律**留空并记 `price_dropped` 诊断**，绝不让同一数字被
> 当成两个字段。标注者遇到抽取器留空时，请按 §4.4 正常判定并在 `notes` 说明。

### 4.5 `information_type`（MACRO / TECHNICAL / NEWS / SENTIMENT / POSITIONING / OTHER）

按**主要驱动**判定。**完整阶梯与优先级以 §4.9 规则 9 为唯一准绳**（2026-09-13 二次裁决后为）：
`POSITIONING`（持仓 / 资金流 / ETF）> `MACRO`（宏观数据 / 央行 / 利率）>
`NEWS`（突发消息 / 事件）> **操作价位（仅当情绪/消息只是背景时）→ `TECHNICAL`** >
`SENTIMENT`（情绪为主旨或明确交易理由）> `OTHER`。
> **注意**：本节此前的旧顺序（`MACRO` > `NEWS` > `POSITIONING` > `SENTIMENT` > `TECHNICAL`）
> 已被二次裁决**取代**——原因是人工金标准里存在"持仓数据 + 宏观跟踪"仍判 `POSITIONING`
> （`mock-post-0028`）、"情绪句只是背景附注 + 明确操作价位"判 `TECHNICAL`（`mock-post-0009`）
> 等反例。**冲突时以 §4.9 规则 9 为准。**
次要类型写入 `rationale`（不新增列，保持与 `docs/04 §10` 一致）。

### 4.6 `rationale`（无观点时可为空）

- 必须含**可复核的原文片段**（≤120 字），不得只写结论；
- 特殊情形必须带标记词：`conditional`、`quote-only`、`post-hoc`、`image_only`。

### 4.7 `instrument`（可空）

- 只标注正文**明确指向**的标的（XAUUSD / DXY / US10Y / USDCNY / XAGUSD / WTI / BTC…）；
- 未明确指向任何标的 → **留空**（禁止默认 XAUUSD）；
- "黄金 / 金价 / gold" 统一映射到 `XAUUSD`（本系统黄金为第一标的）。

### 4.8 版本字段

- 抽取器：`parser_version`（如 `mock-regex-v1`、`llm-deepseek-v1`）——数据库 NOT NULL；
- 人工标注：`annotation_version`（规范版本 + 标注人 + 日期，如 `spec-v0.1-zhang-20260912`）；
- 传播关系用 `model_version`（`docs/04 §11`）。

### 4.9 人工裁决结论（2026-09-13 冻结）——**LLM 提取器 Prompt 的唯一依据**

本节是 2026-09-13 完成的 **226 格人工裁决**（对豆包 / 千问 / 文心三模型分歧样本的逐条裁定）
所得出的口径，直接否决了"抽不到就退回 `no_opinion`"的旧行为。
**修改本节必须走 §9 变更流程，并重跑 `scripts/evaluate_extractor.py` 复评。**

> **二次裁决（2026-09-13，试点后）**：20 条 LLM 试点暴露 3 个问题后由人工追加裁决，
> 均已写入下方规则，并由 `opinion-prompt-v2` 逐条实现（`src/processors/prompt_opinion.py`）：
> ① 规则 4 的 `no_opinion` 语义（TD-26）；② 规则 8 的金标准分层（human 为唯一绝对标准）；
> ③ 规则 9 的 `information_type` 决策阶梯（TD-25）。

1. **条件句（`conditional`）→ `stance = UNKNOWN`，但点位与信息类型仍必须输出**：
   - 方向不猜（"如果…才会转做空" ≠ 做空）；
   - `information_type` 按**条件所依据的驱动**标注（"如果 CPI 超预期…" → `MACRO`；
     "若跌破 2380…" → `TECHNICAL`；"若美联储降息…" → `MACRO`）；
   - 文本给出的数字照标（人工裁决在对抗样本上同样填了 `stop_loss` / `take_profit`）。
2. **引用句（`quote-only`）→ `stance = UNKNOWN` + `information_type = OTHER`**：
   整句是他方观点、作者未表态；点位若文本给出仍照标（不因"引用"而丢弃数字）。
3. **复盘句（`post-hoc`）→ `stance = UNKNOWN`**（不构成前瞻观点）；
   `information_type` 按复盘内容的驱动（多为 `TECHNICAL` / `NEWS`）；点位仍照标。
4. **`stance = UNKNOWN` ≠ 无观点**（本次裁决影响最大的一条）：
   只要文本含**点位**或**信息类型线索**，`opinions` 就必须非空。
   **2026-09-13 二次裁决（TD-26）补充 `no_opinion` 语义**：
   - `no_opinion = true` 表示"**没有可交易的方向性观点**"，此时**仍要输出**它能提供的字段——
     典型：**宏观数据播报 → `stance=UNKNOWN` + `information_type=MACRO` + `no_opinion=true`**；
   - `opinions = []` **只用于**连信息类型线索都没有的帖子（纯寒暄、纯链接、纯图片）；
   - 换句话说：`no_opinion=true` 允许与"1 条 `UNKNOWN` 观点"并存，二者**不矛盾**
     （前者说"没有方向性结论"，后者说"这段文本讲了什么"）。
5. **弱化 / 双重否定措辞**（不排除 / 或许 / 可能 / 倾向）**不足以构成方向**：
   本次 226 格裁决里 **14 格方向全部判 `UNKNOWN`**（"不排除做多"这类只表达倾向、不表态的句子
   也判 `UNKNOWN`，与 §4.1 规则 5 一致）；仅当文本另有**明确方向动词**
   （做多/看空/买入/卖出…）时才判方向，且 `confidence` 上限 0.4（强弱化词）或 0.5（一般弱化词）。
   `information_type` 按驱动，无宏观 / 消息线索时取 `TECHNICAL`。
6. **图表无文字（`image_only`）**：`stance = UNKNOWN`；文本含价格数字 →
   `information_type = TECHNICAL`，点位照标（后续 OCR 阶段再补图内信息）。
7. **多目标取第一目标**：文本同时给出"第一目标 / 第二目标"时，`take_profit` 取
   **第一目标**（44 条人工裁决里 11 条属此类，**11/11 全部取第一目标**）；
   `stop_loss` 同理只填**一个**值，文本未给出则留空（NULL，禁止用 0 或默认值冒充）。
8. **配套评估口径**（与 `docs/08 §5` 并用）：
   - 验收**只看** `source=human-adjudicated` 子集；`source=3-model-consensus` 子集仅作参考
     （模型输出不是金标准，见 `.clinerules`）；
   - **2026-09-13 二次裁决（金标准分层）**：`human-adjudicated` 是**唯一绝对金标准**；
     与共识子集**不要求一致**，报告中**必须标注来源分层**。特别地，
     `3-model-consensus` 是在本节冻结**之前**由三个模型生成的，其"未给出"格与冻结后的口径
     可能冲突（实测典型：条件句/引用句的点位，人工口径要求**照标**，共识却写"未给出"→
     会把正确抽取误记成 `spurious`）。**跨来源比较只看人工子集**；
   - 报数时必须**区分**"该判未判（missed）/ 提取错误（wrong_value）/ 不该判却判（spurious）"；
   - `entry_low` / `entry_high` 本轮**未纳入金标准**，评估时只报**覆盖率**，不报准确率
     （下一轮抽样补入口径后再评）。
9. **`information_type` 决策阶梯（2026-09-13 二次裁决，TD-25；Prompt 必须逐条落实）**——
   口径：**"操作优先，驱动决定分类"**。按顺序判断，**命中即停**：
   - **L1 持仓 / 资金流驱动**（ETF 持仓、投机净多头/净空头、增减仓、持仓变化、资金流）→ `POSITIONING`；
   - **L2 宏观驱动**（CPI/PCE/非农/FOMC、利率、美债收益率、美元指数、通胀、就业）→ `MACRO`；
   - **L2.5 消息 / 事件驱动**（突发消息、地缘或政策突发事件；**消息被指为波动来源**）→ `NEWS`
     （2026-09-13 二次裁决新增：枚举里本就有 `NEWS`，但旧阶梯漏了这一级，
     导致消息驱动帖全部落到 `TECHNICAL`；依据 `mock-post-0060/0090/0170`）；
   - **L3 操作价位优先**：文本含**明确入场 / 止损 / 目标价** → `TECHNICAL`（**即使提到情绪背景**）。
     但有**两个例外**必须按驱动分类（依据 `mock-post-0059/0089` 等）：
     (a) 情绪/风险偏好被明确写成**交易理由**（与方向有因果连接）→ `SENTIMENT`（走 L4）；
     (b) 消息/事件被明确写成**波动来源或交易理由** → `NEWS`（走 L2.5）。
   - **L4 情绪 / 风险偏好**是文本**主旨**（且无明确操作价位），或是 L3 的例外 (a) → `SENTIMENT`；
   - **L5 引用 / 转述他人观点**（作者未表态）或事后复盘且无其它驱动 → `OTHER`；
   - **L6 只有图表、无任何驱动** → `TECHNICAL`；仍无法归类 → `OTHER`。
   - **判别线（"是交易理由，还是背景/附注"）——只作用于 L4 情绪与 L2.5 消息**：
     - **交易理由**：情绪/消息句与方向之间有**因果连接**（"因此 / 所以 / 受此影响 / 导致 / 引发"），
       或该句本身就在解释方向来源（"风险偏好转弱，因此做多""消息引发波动率跳升"）；
     - **背景附注**：情绪/消息只出现在补充说明里（"关注 risk-on 情绪""盘面情绪指标显示多空分歧"），
       不解释方向来源 → 只算背景 → 走 L3 判 `TECHNICAL`。
     - `L1` 持仓/资金流 与 `L2` 宏观 照常按各自规则判断：**既不许**因为判别线把宏观/持仓降级成
       `TECHNICAL`，**也不许**把一笔带过的宏观/情绪尾句升格成 `MACRO`/`SENTIMENT`。
     - 注：泛泛的"宏观环境/宏观面"与免责声明式提及（"若宏观环境变化将及时更新"）**不算**宏观驱动。
   - **优先级总链条**：`L1 持仓 > L2 宏观 > L2.5 消息 > L4/L2.5 例外（驱动是理由时）
     > L3 操作价位（情绪/消息仅背景时）> L5 引用/复盘 > L6 兜底`。
     人工金标准依据：`0015/0025`（ETF 持仓 + 完整点位）→ `POSITIONING`；`0027`（美债 + 点位）→ `MACRO`；
     `0060/0090/0170`（消息为波动来源 + 点位）→ `NEWS`；`0059/0089`（情绪为交易理由 + 点位）→ `SENTIMENT`；
     `0009/0020`（情绪仅背景 + 点位）→ `TECHNICAL`；`0007/0023`（纯情绪、无价位）→ `SENTIMENT`；
     `0019`（复盘）→ `OTHER`；`0004/0005`（无驱动纯操作）→ `TECHNICAL`。
   - **已知残余边界（TD-29，待真实语料复核）**：**"操作块 + 驱动尾句"**这一形态在现有金标准里
     既出现过 `MACRO`（`0027`「…日内交易. 关注美债收益率回落，支撑金价估值」）、
     也出现过 `TECHNICAL`（`0009`「…日内交易. 关注 risk-on 情绪主导，黄金短线承压」+ 宏观跟踪尾句），
     以及 `SENTIMENT`（`0079/0109/0119/0139` 等）。模型在这类模板上无法稳定复现人工选择，
     属**口径边界而非模型能力问题**；须用**真实作者帖子**重新裁决后再收敛（不得为刷分继续调 Prompt）。

## 5. 输出结构（严格 JSON Schema）

抽取器（Mock 或 LLM）的输出必须是**严格遵循下述 Schema 的单个 JSON 对象**，
字段名、类型、取值与 `author_opinions` 一一对应；**禁止多余字段**（`additionalProperties: false`），
禁止用自然语言包裹（不得输出"好的，结论是……"）。校验实现用 Pydantic（`extra="forbid"`），
Schema 与 Pydantic 模型必须保持同步（下一步交付 `src/processors/schemas.py`）。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "AuthorOpinionDraft",
  "type": "object",
  "additionalProperties": false,
  "required": ["stance", "parser_version"],
  "properties": {
    "stance": { "enum": ["LONG", "SHORT", "FLAT", "UNKNOWN"] },
    "instrument": {
      "type": ["string", "null"],
      "enum": [null, "XAUUSD", "XAGUSD", "COMEX_GC", "SGE_AU9999", "DXY", "US10Y", "US02Y",
               "US10Y_REAL", "USDCNY", "WTI", "BTCUSD"]
    },
    "horizon": { "enum": [null, "15m", "30m", "1h", "4h", "1d"] },
    "confidence": { "type": ["number", "null"], "minimum": 0, "maximum": 1 },
    "entry_low": { "type": ["number", "null"], "exclusiveMinimum": 0 },
    "entry_high": { "type": ["number", "null"], "exclusiveMinimum": 0 },
    "stop_loss": { "type": ["number", "null"], "exclusiveMinimum": 0 },
    "take_profit": { "type": ["number", "null"], "exclusiveMinimum": 0 },
    "information_type": {
      "enum": [null, "MACRO", "TECHNICAL", "NEWS", "SENTIMENT", "POSITIONING", "OTHER"]
    },
    "rationale": { "type": ["string", "null"], "maxLength": 2000 },
    "parser_version": { "type": "string", "minLength": 1, "maxLength": 50 }
  }
}
```

**契约细节（避免实现分歧）**

1. `effective_at` **不在抽取器输出中**：它由管道从 `author_post.effective_at` 注入，
   防止模型编造时间（防泄漏的关键设计）。
2. 一条帖子产生多条观点时，抽取器输出**数组**（`AuthorOpinionDraft[]`）；
   空数组表示"本帖**连信息类型线索都没有**"（纯寒暄/纯链接/纯图片）。
   **注意（2026-09-13 二次裁决）**：文本级标记 `no_opinion` 位于外层对象，
   且允许与"1 条 `stance=UNKNOWN` 观点"并存（宏观数据播报 = `UNKNOWN` + `MACRO` + `no_opinion=true`）；
   但**不要**用 `stance=UNKNOWN` 冒充"无观点"（前者是"有观点但无法判定方向"）。
3. 数值用 JSON number；落库前转换为 `Decimal`（`NUMERIC(20,8)` / `NUMERIC(12,10)`），
   **禁止 float 传输关键金融数值**（`docs/02 §5`）。
4. 任何字段无法判定 → `null`（不是 0、不是空字符串、不是 "N/A"）。
5. 抽取失败（文本不可解析）必须抛错并计入 `processed_items.status=FAILED`，
   禁止返回"看起来合法"的默认值。
6. **`instrument` 的枚举是"已知集合"**（与 `database/seeds/instruments.py` 白名单一致，
   由测试锁定不漂移）；实现层实际采用**格式校验**（`^[A-Z][A-Z0-9_/]{1,19}$`）+
   未知代码告警：新标的（如 `XPTUSD`）不会被拒绝，但必须先在 `instruments` 白名单落库，
   否则数据库外键会拦截（禁止凭空造标的）。

## 6. 标注流程与质量控制

1. **准备**：抽样脚本导出标注 CSV（附录 A），含随机种子与分层信息；
2. **盲标**：标注者 A 独立标注全部 200 条；标注者 B 独立标注其中 20%（40 条）；
3. **一致性检查**：对 A/B 重叠样本计算 **Cohen's Kappa**：
   - `stance` 目标 **κ ≥ 0.80**；`horizon` 目标 **κ ≥ 0.75**；
   - 未达标 → 先修规范（补边界规则），**不得**先改抽取器；
4. **仲裁**：A/B 分歧由第三人按本规范裁决，裁决理由写入 `notes`；
5. **比对**：抽取器输出（CSV/JSONL）与仲裁后的标注合并，生成混淆矩阵与指标（§7）；
6. **留痕**：抽样种子、规范版本、标注人、比对脚本版本一并归档（可复现）。

## 7. 验收指标（Phase 2 门槛）

`docs/05` 要求"随机抽样 200 条观点进行人工对照"，因此必须同时报告以下指标
（**报告值 + 分层细分**，不允许只报一个总准确率）：

> **评估口径（2026-09-13 冻结，见 §4.9 第 8 条）**：验收**只认**
> `source=human-adjudicated` 的人工裁决子集；`source=3-model-consensus` 子集仅作参考
> （`.clinerules`：模型输出不得充当验收依据）。报数时必须**分别列出**
> "该判未判（missed）/ 提取错误（wrong_value）/ 不该判却判（spurious）"，不得只给一个准确率。
> 评估工具：`scripts/evaluate_extractor.py`（输出 `logs/extractor_eval.csv` + 基线评估报告）。

| 指标 | 计算方式 | 建议门槛（待团队确认） |
|---|---|---|
| `stance_accuracy` | 抽取 `stance` 与仲裁标注一致的比例（含 UNKNOWN；附混淆矩阵） | ≥ 0.90 |
| `horizon_accuracy` | 仅在 `stance` 正确的样本上计算 `horizon` 一致率 | ≥ 0.85 |
| `entry_accuracy` | 仅在正文有明确点位的样本上，`entry_low/entry_high` 完全一致率 | ≥ 0.90（与 `docs/08 §5` 对齐） |
| `confidence_validity` | (a) 与人工分档的 Spearman 相关 > 0；(b) ECE（校准误差）≤ 0.15；不允许"含糊文本高分" | 见左 |
| `no_opinion_accuracy` | 人工标 `no_opinion=true` 的样本被抽取器判为"无观点"的比例 | ≥ 0.90 |
| `coverage` | 产生 ≥1 条观点的帖子占比 | **仅报告，不设门槛** |

**红线圈（任何一条不满足即不得进入 Phase 2 验收）**

- 出现 `leakage_suspect=true` 的样本被计入准确率（必须剔除并单独统计）；
- 通过降低 `UNKNOWN` 比例"刷" `stance_accuracy`（必须同时报告 `unknown_rate` 与拒答明细）；
- 只用"明确 LONG"这类简单样本报告指标（必须含 §2.2 的对抗样本分层结果）。

## 9. 变更流程

1. 本规范由团队评审后版本号从 `v0.1` 起递增；变更必须说明"影响的字段与判定规则"；

3. 抽取器版本（`parser_version`）与规范版本（`annotation_version`）必须同时记录，
   任何指标都必须标明"在哪个规范版本下、针对哪个解析器版本"测得；
4. 禁止为了提高分数而修改本规范（规范是标尺，不是被优化的对象）。
